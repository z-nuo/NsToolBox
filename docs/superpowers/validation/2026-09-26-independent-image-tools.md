# 图片独立工具修正验证

日期：2026-09-26。用户场景与当前验收状态见 [NST-026](../../development/TROUBLESHOOTING.md#nst-026)。设计更新见 [图片处理设计](../specs/2026-09-25-image-tools-design.md)。

## 改动范围

抠图、缩放、格式转换和压缩各自持有图片、参数、错误与结果；执行时仅构造当前工具需要的参数。抠图保留原尺寸并输出透明 PNG，缩放保留源格式，转换/压缩保留尺寸。按钮明确命名操作。

显式“将此结果用于…”复制选中结果快照到目标工具并选中新图片，等待手动开始。重新处理的结果使用不同缓存路径，避免被目标列表误判为已导入的旧结果；源工具的后续清空不影响目标快照。图片结果的格式元数据按实际输出显示。

## 验证与实际证据

环境：Intel、macOS 26.7、Swift 6.3.3、SDK 26.5。

- 旧行为复现：测试先对纯白图做人像抠图，切到格式转换后导入另一纯白图；`swift run ToolboxUITests --image-isolation-only` 退出 1，仍报“未检测到人像”。最初蓝矩形样本被 Vision 判为人物，未能作为稳定失败前提，已改为纯白样本。
- 修正后隔离用例：同命令退出 0，转换为 JPG 成功且尺寸保持 512 × 512。切回抠图后其原错误、原图及人像参数仍保留。
- 完整状态与原生工作流：`swift run ToolboxUITests --render --capture` 退出 0。新增用例在真实 NSHostingView 窗口发送标签点击事件；格式转换不执行被注入的人像和非法尺寸参数。
- 显式传递：导入目标时不自动处理；源工具清空后目标快照字节不变。JPEG 缩放仍为 JPEG，压缩保留尺寸；重新生成后再次传入目标时产生第二个独立输入并选中它。
- 既有去重、无效图片隔离、导出失败重试、不覆盖旧文件、取消、参数失效、会话清理与真实 AppKit 退出检查继续通过。
- 七个窗口截图返回 0；检查 780 × 640 图片工作区浅深色真实截图，当前动作、结果转交菜单、原图/结果和尺寸信息正常显示；两种外观的结果像素断言通过。

`./scripts/build-app.sh` 退出 0；lipo 确认 x86_64 / arm64，vtool 两架构最低 macOS 14.0，codesign 严格验证退出 0。`git diff --check` 与更新文档链接检查通过。代码提交：`ced56a4`。临时日志为 build/image-isolation-red.log、build/image-isolation-green.log、build/image-independent-ui.log、build/image-independent-build.log；截图位于 build/previews，均不纳入 Git。
