## 产品方向与取舍

建议定位为本地办公与开发工具箱，保留 macOS 14、Intel / Apple Silicon、原生紧凑界面和图片处理默认入口。

可选方向有三种：继续深耕图片处理、同时补齐多种高频工具、扩展成截图录屏与自动化平台。根据用户选择，推荐第二种，按小批次交付。第一种无法覆盖文件和开发工作；第三种增加权限、后台任务和维护成本，现阶段收益不够明确。

## 建议工具集

下表均为候选新增能力。已有 JSON、Base64、URL、抠图、缩放、PNG/JPG 转换与基础压缩继续保留。

| 工具集 | 优先新增 | 后续候选 | 使用场景 |
| --- | --- | --- | --- |
| 图片处理 | 裁剪、旋转、翻转；图片信息与透明度检测；OCR | 图片拼接、文字/图片水印、标注与实色遮盖、颜色取样、扩展格式、目标体积压缩 | 调整素材、提取截图文字、确认是否真正透明 |
| 开发工具 | 时间戳与时区转换；UUID；文本哈希；正则测试 | JWT 解析、JSON/YAML、JSONPath、Cron 预览、SQL/XML 格式化、进制转换 | 查日志时间、生成标识、校验数据、调试表达式 |
| 文本工具 | 纯文本对比；按行去重/排序/清理 | 批量替换、大小写转换、字符统计、Markdown 预览、CSV/JSON 互转 | 比较配置和日志、整理名单或数据 |

## 分批顺序

### 第一批：日常高频能力

1. 图片裁剪 / 旋转 / 翻转：自由裁剪、常用比例、90 度旋转与镜像，预览后导出新文件。
2. 图片信息：尺寸、实际格式、体积、色彩信息；区分“无 alpha”“有 alpha 但完全不透明”“存在透明像素”，避免将 PNG 扩展名等同于透明背景。
3. 时间戳：秒与毫秒输入、日期互转、明确显示时区。
4. UUID 与文本哈希：独立入口，支持复制；哈希明确算法，不称为加密。
5. 纯文本对比：左右输入，行级差异与差异跳转；与 JSON 的结构化对比区分。
6. 批量重命名：替换、前后缀、序号；原名/新名实时预览，冲突标记后再执行。

以上为建议范围，按工具逐个交付和验收。批量重命名需要单独设计失败恢复与撤销条件，不能直接套用图片导出行为。

### 第二批：图片与文档衔接

- 本地 OCR：图片预览与可复制文字，先验证中英文，首版不承诺表格或复杂排版还原。
- 图片拼接、水印、截图标注与遮盖。
- 图片合成 PDF、PDF 转图片、合并与拆分。
- 文件哈希、文本清理、正则、JWT 解析。

### 第三批：质量与效率

- WebP / HEIC 等格式扩展：分别验证 macOS 14 的读取与写出能力、透明度和编码质量；必要依赖单独评估。
- 更有效的 PNG 优化、可选有损模式、目标体积压缩：提示是否改变尺寸/质量，无法达到目标时明确报告，不承诺任意图片都能压到指定 KB。
- 批量预设、Finder 快捷入口、工具收藏与最近使用。
- 重复文件扫描：先按大小与哈希筛选，再确认内容；首版只列结果，不自动删除。

暂缓全功能视频编辑、截图录屏平台、完整 PDF 文字排版编辑、云同步、AI 生图和系统清理。这些能力需要独立投入，不能视为给现有工具加一个按钮。

## 交互约束

- 左侧保留工具集，顶部显示当前集的工具；工具增多后支持搜索和溢出入口，避免标签挤压工作区。
- 继续默认打开图片处理。新增工具集不会改变启动偏好。
- 每个工具保存自己的输入、参数、错误与结果，不隐式继承其他工具的操作。
- 连续处理使用显式“将结果用于…”；预设只在用户主动选择后应用，并展示即将执行的步骤。
- 图片沿用左侧原图、右侧结果；文本沿用左右编辑器；重命名采用原名/新名表格；PDF 采用页面缩略图与结果预览。保持紧凑风格，布局按任务需要调整。
- 全局工具搜索建议使用 Command-K；默认不主动读取剪贴板，用户粘贴或触发识别时再推荐工具。
- 文件类操作区分“处理预览”和“写入文件”。重命名提前检查同名冲突，保留操作记录；图片/PDF 默认导出新文件，避免覆盖源文件。

## 实现前需核对

此文档未验证 Apple API 可行性，不给出工期承诺。OCR、PDF、格式编码和 Finder 集成需在对应批次核对官方 API、macOS 14 支持情况，并分别验证 Intel 与 Apple Silicon。

纯文本哈希可与后续文件哈希复用算法实现，但文件读取需流式处理。JWT 解码不等于签名有效，界面必须明确验证状态。PDF 的视觉遮盖与真正移除内容是不同能力，不能混称“脱敏”。

调研阶段只做规划；后续实现和验证结果另行记录。开发与测试的新问题继续记录到 [开发问题列表与修复指南](../../development/TROUBLESHOOTING.md)。
